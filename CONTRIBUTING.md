# Contributing

Read the architecture, security policy, source attribution, and current build status first. Follow the vertical-module order. Discuss shared contract changes before modifying another contributor's interface.

Use fictional fixtures. Write regression tests before fixes. Run formatting, lint, types, unit, integration and browser checks before requesting review. Never remove assertions to make a failing implementation pass. Keep migrations forward-only and checked in. Document all API changes and coverage.

Do not include student information, production snapshots, credentials, or live verification links in issues, logs, screenshots, tests, or pull requests. Report vulnerabilities privately to the repository operator; a public disclosure contact must be configured before public release.
